# Deadline Tracker — Calculation & LLM Safety Steering

Governs all code for the deadline tracker feature (`.kiro/specs/deadline-tracker/`).

## The LLM never calculates deadlines
- All deadline dates are computed by **pure functions** in
  `frontend/src/utils/deadlineCalculations.ts` (and `computeDeadlines.ts`).
- Bedrock / the AI layer MUST NOT compute, infer, or adjust any deadline date.
- The LLM may only **explain** a deadline when it is handed the already-calculated date
  and the static definition. It receives the date as a given fact; it never derives it.

## Determinism
- Given the same profile dates, the same deadlines must always be produced
  (REQ-NF-1). No randomness, no "today" baked into stored values — tiers are recomputed
  on every render from the current date.
- Every formula must have a unit test, including missing-source and edge cases.

## Regulation citations are hardcoded
- CFR cites (e.g. `8 CFR 214.2(f)(11)(i)(A)`) and official USCIS/SEVP URLs live in the
  static `deadlineDefinitions.ts`. They must NEVER be generated by the LLM.
- If a cite or official URL is unknown, leave it blank — do not let the model invent one.

## Accuracy over guessing (REQ-NF-4)
- If required profile dates are missing, show "Complete your profile" — never show a
  wrong or guessed date. Prefer showing nothing.

## Not legal advice
- Deadlines are estimates to help users organize, not legal guarantees. The existing
  responsible-ai.md disclaimer applies to every deadline surface and reminder email.
